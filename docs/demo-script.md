# 5 分钟演示脚本

## 0. 演示前检查（30 秒）

1. 后端：

```bash
cd backend
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

2. H5：

```bash
cd frontend
npm run dev:h5 -- --host 127.0.0.1 --port 5173
```

3. 浏览器打开 <http://127.0.0.1:5173>，建议 375 × 812 或手机尺寸。
4. 右上角条件确认：**浙江 / 无会员 / 未启用旧机**（答辩默认）。
5. 购物车如为空，演示时点“载入示例购物车（3 件）”。

**备用方案**：如果现场网络或 H5 异常，直接播放提前录好的 5 分钟视频；后端与前端均为本地服务，不依赖外网。

---

## 1. 开场：痛点（30 秒）

> “同一台手机，四个平台四个价；店铺券、平台券、满减、国补、以旧换新、返利，规则互相嵌套。消费者不是不想省，是算不过来。价策做的不是价格聚合，而是把规则算成一条可执行的购买路径。”

打开首页，指向：

- “别只看标价，看最终到手价。”
- 右侧“价格侦探”：拼多多 90 天价格带，疑似先涨后降。
- 四个快捷入口：国补计算器、购物车拆单、价格侦探、全部比价。

---

## 2. 单商品反转：标价最低 ≠ 到手最低（90 秒）

1. 点“值得算一算”里的 **星海 X1 Pro 手机**。
2. 指向平台卡：
   - 拼多多标价 **5299**，看起来最低；
   - 京东 **5599**；
   - 抖音 **5649**；
   - 淘宝 **5099**，最优。
3. 展开价格瀑布：
   - 页面标价 5999；
   - 店铺券 -400；
   - 手机购新补贴 -500；
   - 到手 5099。
4. 展开平台卡“查看优惠明细”：
   - 拼多多/京东/抖音的国补被拒：“该平台暂不参与这项补贴”；
   - 淘宝的国补按券后价 15% 估算，封顶 500。
5. 点“查看购买策略”：
   - 两步：领店铺券 → 申请国补；
   - 备选平台为什么不是它们；
   - 未采用优惠的原因。

**一句话**：  
> “引擎不是把价格排个序，而是把每张券的资格、门槛、顺序都算进去，再告诉你先做什么、后做什么。”

---

## 3. 会员改变赢家（45 秒）

1. 返回首页或比价列表，打开 **灵越 Air 14 笔记本**。
2. 默认无会员：京东 **4269.10** 最优。
3. 点右上角条件 → 勾选 **88VIP** → 应用。
4. 页面重新计算：淘宝 **4103.14** 最优；返利 82.06，净价 **4021.08**。
5. 策略页显示 4 步：店铺券 → 88VIP 95 折 → 电脑补贴 → 返利。

**一句话**：  
> “同一个人、同一件商品，会员身份不同，最优平台就不同。这不是静态比价表能回答的。”

---

## 4. 购物车拆单 + 凑单（90 秒）

1. 切到“购物车”。如果为空，点 **载入示例购物车（3 件）**：
   - 云鲸扫地机 2920；
   - 声阔耳机 1199；
   - 极光投影仪 2899。
2. 结果：
   - 拆成 2 单：京东 + 淘宝；
   - 合计 **6538**；
   - 全部在淘宝 6817，省 **279**；
   - 京东单还差 80 元可用“满 3000 减 300”。
3. 点凑单建议里的 **加购 89 元收纳盒**：
   - 京东单变成 2709；
   - 合计 **6327**；
   - 比刚才再省 211，还多拿到一件商品。
4. 回到数量/移除，展示会重新计算。

**一句话**：  
> “拆单不是拍脑袋，是把‘每件商品去哪个平台’当成划分问题枚举；凑单也不是让你多买，而是算清加购后的净增。”

---

## 5. 国补计算器：规则与资格（45 秒）

1. 首页 → 国补计算器。
2. 默认：手机 / 5999 / 淘宝 / 浙江 → 预计可减 **500**。
3. 把平台切到 **京东** → 预计可减 **0**，原因“该平台暂不参与这项补贴”。
4. 打开以旧换新，填旧机估值 300 → 京东出现以旧换新抵扣（若平台支持）。
5. 指向规则卡片的版本与生效期：“规则是 JSON 配置，不是写死的 if-else。”

**一句话**：  
> “政策会变、地区会变、平台会变，所以我们把规则做成可配置、带版本和生效期的数据。”

---

## 6. 价格侦探：先涨后降（30 秒）

1. 首页 → 价格侦探，或商品详情 → 价格走势。
2. P001 拼多多：
   - 当前 5299；
   - 90 天中位 6186.76；
   - 当前分位 1.1%；
   - 近两周出现抬价，判定“疑似先涨后降”。
3. 切到京东/淘宝/抖音，价格带与分位不同。

**一句话**：  
> “低价不等于真降价。我们同时看历史分位和促销前的价格行为。”

---

## 7. 技术收尾（30 秒）

指向 README / 架构图（可切到 `docs/architecture.md`）：

- 单商品：DFS + 分支限界 + 记忆化，14 条优惠平均 10ms；
- 购物车：≤6 件精确枚举，6 件平均 829ms；
- 20+ 项测试，含“剪枝 vs 暴力枚举”差分测试；
- 数据合规：不抓页面；演示数据 + 用户提交 + 联盟 API 适配层；
- 双端：uni-app 一套代码 → H5 + 微信小程序。

**结束语**：  
> “价策的竞赛价值不在‘比价’两个字，而在把多平台、多优惠、多政策规则变成一个可求解、可解释、可执行的决策问题。”

1. 首页一句话定位。
2. P001：拼多多 5299，淘宝 5099（券 400 + 国补 500）。
3. 切 88VIP：P002 京东 4269.10 → 淘宝 4103.14。

## 现场可能追问

| 问题 | 30 秒回答 |
|---|---|
| 数据哪里来？ | 演示数据 + 用户提交 + 联盟 API 适配层；不抓页面，页面显著标注演示数据。 |
| 大厂做了怎么办？ | 大厂做站内券；我们做跨平台、跨补贴类型的决策层，可作为导购/联盟合作方。 |
| 规则变了怎么办？ | 规则 JSON 化、版本化、带生效期；改配置不改引擎。 |
| 为什么用户不直接看平台？ | 平台不会告诉你别的平台更便宜，也不会替你拆单、凑单、算国补。 |
| 算法会不会太慢？ | 单商品 14 条优惠 10ms；6 件购物车 829ms；有基准与差分测试。 |
| 商业模式？ | 联盟佣金、导购服务、规则 SaaS；先做工具与可信度。 |
| 为什么不做爬虫？ | 不合规、易失效；竞赛作品不应把违规能力当卖点。 |

# 竞赛价值评估：为什么“价策”值得参赛

> 本文是对最初问题的直接回答：这个比价小程序有竞赛价值吗？
> 结论：**有，但前提是把“比价”升级为“购买策略求解”。**

## 1. 一句话判断

- 只做“聚合各平台价格”：技术开发类竞赛约 **5/10**，同质化严重。
- 做成“可解释的优惠叠加 + 国补规则 + 跨平台拆单”引擎：约 **8/10**，有算法、有演示、有社会价值。

本项目已经按后一种路线落地，并在代码中提供了可复现证据。

## 2. 评分维度

| 维度 | 只做价格聚合 | 本项目 | 依据 |
|---|---|---|---|
| 创意新颖度 | 4/10 | 7/10 | 从“最低价”推进到“购买步骤与拆单”，国补资格引擎少见 |
| 技术难度 | 5/10 | 8/10 | 带门槛/互斥/顺序/资格约束的组合优化；DFS + 分支限界；购物车划分枚举 |
| 完成度可控 | 9/10 | 8/10 | 演示数据稳定、双端可跑、API 与测试齐全 |
| 演示效果 | 6/10 | 9/10 | 88VIP 切换改变最优平台；89 元凑单让总价下降 211 元 |
| 社会/实用价值 | 7/10 | 8/10 | 降低规则理解成本，帮助国补政策落地，识别先涨后降 |
| 数据合规风险 | 低 | 中 | 主动声明演示数据，不做爬虫，预留联盟 API 适配层 |

## 3. 与常见产品的差异

| 产品 | 主要能力 | 本项目差异 |
|---|---|---|
| 慢慢买 | 价格历史、全网比价 | 本项目进一步求解“怎么买最省”，并把国补/以旧换新纳入 |
| 什么值得买 | 优惠内容、社区 | 本项目不靠内容，靠约束求解与可解释策略 |
| 购物党 | 浏览器比价插件 | 本项目输出跨平台拆单与凑单建议，而非单商品价格 |
| 返利网 | 返利导购 | 本项目把返利作为净价的一部分，并解释其对支付价的影响 |
| 平台自身优惠页 | 站内券 | 本项目跨平台、跨补贴类型统一建模 |

## 4. 三个可讲的技术点

### 4.1 优惠叠加是约束优化，不是加法

优惠之间存在：

- 门槛：满 3000 减 300，按原价还是券后价；
- 互斥：平台券与国补不可同享；
- 顺序：会员价、国补、支付立减、返利按平台规则有先后；
- 上限：百分比补贴封顶 500；
- 资格：地区、会员、以旧换新、价格上限、品类。

单商品求解器用 DFS + 分支限界 + 记忆化，在毫秒级找到最低实付；购物车把“每件商品去哪个平台”建模为划分问题，≤6 件时精确枚举。

**可验证证据**：随机差分测试（剪枝结果与无剪枝暴力枚举一致）、23 项自动化测试全绿、性能基准。

### 4.2 政策规则可以像代码一样配置

国补不是写死的 if-else，而是 JSON 规则：

- 地区、品类、平台、价格上限；
- 百分比、封顶金额；
- 是否要求以旧换新；
- 生效期、版本、来源。

答辩时可以现场改一条规则，重新计算，展示“规则驱动”的工程能力。

### 4.3 可解释性让结果可信

每个平台输出：

- 采用了哪些优惠、顺序、金额；
- 没采用的优惠及原因（差多少门槛、与谁互斥、地区不符、超出价格上限）；
- 备选平台比最优贵多少，以及贵的原因。

这比“黑盒给一个最低价”更适合竞赛答辩，也更适合真实消费决策。

## 5. 演示中的“反直觉”时刻

1. **标价最低 ≠ 到手最低**：拼多多 5299，淘宝叠加券和国补后 5099。
2. **会员改变赢家**：P002 无 88VIP 时京东 4269.10；开通后淘宝 4103.14。
3. **加购反而更省**：3 件购物车 6538；加购 89 元收纳盒后 6327。
4. **有补贴规则也可能不符合**：7999 元游戏本超出 7000 元示例上限，引擎解释拒绝原因。
5. **促销可能是先涨后降**：P001 拼多多当前处于 90 天 1.1% 分位，但近两周出现抬价。

这些时刻比“我们聚合了四个平台”更容易被评委记住。

## 6. 社会价值与商业想象

- **消费者**：把复杂的券规则变成可执行步骤，降低决策成本。
- **政策落地**：国补资格与金额计算器可以独立使用，帮助政策触达。
- **价格透明**：历史价格与先涨后降识别，缓解信息不对称。
- **商业模式（远期）**：联盟返利佣金、品牌导购服务、规则 SaaS；竞赛阶段不承诺收入。
- **可复制性**：3C/家电 → 汽车、家装、旅游等高客单价、多优惠规则品类。

## 7. 风险与主动应对

| 评委可能问 | 回答方向 |
|---|---|
| 数据从哪来？是否合规？ | 演示数据 + 用户提交 + 联盟 API 适配层；不抓页面；页面显著标注演示数据 |
| 大厂做了怎么办？ | 大厂做站内券，本项目做跨平台、跨补贴类型的决策层；可被平台/导购合作 |
| 平台规则变了怎么办？ | 规则 JSON 化、版本化、带生效期，引擎不改代码 |
| 为什么用户不直接看平台？ | 平台不会告诉你别的平台更便宜，也不会替你拆单/凑单/算国补 |
| 商业模式是什么？ | 联盟佣金、导购服务、规则 SaaS；先做工具与可信度 |
| 算法是不是过度设计？ | 单商品 10ms 级、6 件购物车 <1s；有基准与差分测试 |

## 8. 不建议的参赛叙事

- 不要把“爬虫抓全网”作为核心卖点：不合规、易失效、答辩风险高。
- 不要宣称“实时全网最低价”：数据无法保证。
- 不要一上来讲全品类、社区、支付闭环：1 个月做不完，评委也会质疑聚焦度。
- 不要把“用了 uni-app / FastAPI”当创新点：技术选型只是实现手段，创新在模型与求解。

## 9. 结论

“价策”的竞赛价值不来自“比价”这个点子，而来自：

> 把消费者面对的多平台、多优惠、多政策规则，建模成一个可求解、可解释、可演示的决策问题。

如果按本文的路线答辩，它是一个有技术深度、有现场效果、有社会价值的作品；如果退化成价格列表，它就只是一个普通的比价小程序。
